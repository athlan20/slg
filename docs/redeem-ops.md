# 兑换码（礼券）运维手册

给运维 / 运营看的。不需要读代码：照着场景抄命令就行。兑换码就是“礼券 / 券号”——玩家在游戏里输入一串 16 位的码，领到元宝或道具。

> 本手册里所有命令都在**后端目录 `backend/`** 里运行，用 `npm run redeem -- <子命令> ...`（注意 `--` 不能漏，它把后面的参数交给脚本）。没有网页后台，所有操作都走这个脚本。

## 一、开始前

1. **在哪台机器上跑**：在部署后端的那台机器上，进入 `backend/` 目录。脚本读 `backend/.env` 里的 `DATABASE_URL` 连数据库（进程环境变量里的同名变量优先）。
2. **先确认连的是哪个库**：脚本不会打印它连了哪个库，所以动手前自己确认：
   - 打开 `backend/.env`，**只看** `DATABASE_URL` 里的主机名和库名（不要把整行贴到聊天或工单里，里面有密码）；
   - 先跑一次 `npm run redeem -- list`：能看到线上已有的批次，说明连对了；如果提示“还没有兑换码批次”而你确定线上已经建过，就是连错库了，先停下。
3. **脚本版本要和线上后端一致**：脚本每次启动都会先把表结构补齐（和后端启动时一样），所以请先部署新版本后端，再在同一份代码里运行脚本。
4. **码是敏感数据**：知道码的人就能领奖励。码只会出现在 `create` 的输出和 `export` 里，库里存的是明文；导出的文件要当密码对待，发完就删，不要贴到公开群聊、工单评论里。

## 二、先理解两个概念

- **批次**：一次生成的一组码，共用同一份奖励和同一个过期时间。每个批次有一个 id（`create` 时会打印）和一个你起的名字（如“礼券-1000元宝”）。**一个批次只有一种面额**，要发多种面额就建多个批次。
- **两种码**：
  | 类型 | 说明 | 用在哪 |
  |---|---|---|
  | `single` 一次性码（默认） | 每个码只能被**一个玩家用一次**；同一个玩家可以兑换同一批的多张 | 礼券、淘宝券号、发给个人的补偿 |
  | `shared` 通用码 | 一个码，多人都能兑，**每人一次**，到人数上限为止 | 社群口令、活动口令 |

奖励可以是元宝（1 到 100000），也可以是道具，或两者都有。元宝永久保留、换季不清零；**福利发的道具换季会清空**。

## 三、常见场景

### 1. 批量生成指定面额的礼券

```bash
# 200 元宝的礼券 1000 张
npm run redeem -- create --name "礼券-200元宝" --kind single --count 1000 --ingot 200

# 1000 元宝的礼券 500 张
npm run redeem -- create --name "礼券-1000元宝" --kind single --count 500 --ingot 1000
```

输出的第一行是 `批次 id：……`，**把它记下来**（后面导出、停用、对账都要用）；下面是每行一个的券号。建议随手把输出存起来：

```bash
npm run redeem -- create --name "礼券-1000元宝" --kind single --count 500 --ingot 1000 | tee create-1000.txt
```

可选参数：

| 参数 | 含义 |
|---|---|
| `--expires 2026-12-31` | 过期时间，写日期 = 当天 UTC 结束；不写就不过期 |
| `--channel taobao` | 渠道标记（字母、数字、连字符，最长 20），对账时按它汇总；大小写统一存成小写 |
| `--item city_order:2` | 再加道具奖励（道具 id:数量，数量 1 到 99，可重复写多个；道具必须是在售的） |

**数量上限**：一次性码单批最多 10000 张。**建议每批 500 张**：一批码万一外泄，损失就是 500 × 面额；用完再建下一批。

### 2. 导出一批码（发给渠道或发货工具）

```bash
# 每行一个券号、没有表头、没有引号（淘宝等发货工具直接导入）
npm run redeem -- export --batch <批次id> --format txt > codes.txt

# 只导出还没兑换、也没作废的码（补发货、重新导入时用，避免把用过的码再发出去）
npm run redeem -- export --batch <批次id> --format txt --unused > codes-unused.txt

# 默认格式是 CSV（第一行表头 code）
npm run redeem -- export --batch <批次id> > codes.csv
```

导出的统计信息在屏幕上显示、不会混进文件里，所以 `> codes.txt` 得到的文件里全是券号。

### 3. 看有哪些批次

```bash
npm run redeem -- list
```

每个批次一行：**批次 id**、名称、类型、渠道、奖励、已兑换 / 总数、已作废、过期时间、状态（启用中 / 已停用）。忘了批次 id 就来这里复制。（一次性码的“总数”包含作废的码；通用码的“总数”是人数上限。）

### 4. 玩家说“码用不了”：查一个码

```bash
npm run redeem -- lookup --code XXXX-XXXX-XXXX-XXXX
```

码不区分大小写，带不带横线都能查。会显示：属于哪个批次、渠道、奖励、**状态**：

| 状态 | 含义 / 怎么答复玩家 |
|---|---|
| 未兑换 | 码是好的。让玩家核对有没有输错，或是不是被限流了（见下面“常见问题”） |
| 已兑换 | 已经被某个账号兑过了。会显示兑换时间和**打了码的**用户名（只露前 2 位和后 2 位），用来核对是不是本人 |
| 已作废 | 之前退款或人工作废过 |
| 批次已停用 | 整批被停用了 |
| 已过期 | 超过了批次的过期日期 |

码不存在会提示“不存在”（脚本以失败退出）。

### 5. 买家退款：作废没兑换的码

```bash
npm run redeem -- void --code XXXX-XXXX-XXXX-XXXX                 # 一个
npm run redeem -- void --code AAAA-... --code BBBB-...            # 多个
npm run redeem -- void --file refund.txt                          # 文件里每行一个
```

- 只能作废**还没被兑换**的码；作废后再兑换会提示无效。
- **已经兑换的码不能作废，也不会收回元宝**：命令会告诉你“已被兑换，不能作废”并给出兑换时间。要不要和买家协商，由你决定。
- 批量作废时，有的码失败不影响其余。每个码打印一行结果；只要有一个“不存在”或“已被兑换”，命令结束时就以失败状态退出（本来就已作废的算成功，重复跑同一个文件不会报错）。

### 6. 停用整个批次（码泄露了）

```bash
npm run redeem -- disable --batch <批次id>
```

这批**还没兑换**的码立即全部失效；已经领走的奖励不收回。之后补建一批新的，把新码发出去。

### 7. 对账

```bash
npm run redeem -- stats --channel taobao --since 2026-11-01 --until 2026-11-30
```

按**北京时间的自然日**汇总该渠道每天的已兑换码数和折合元宝，最后一行合计，另外打印这个渠道的批次总数、码总数、已兑换数、未兑换数、已作废数。`--since`、`--until` 可以不写（统计全部），日期含边界，格式必须是 `YYYY-MM-DD`。

和渠道后台订单数对：**渠道订单数应当大于等于已兑换码数**，差额就是买家拍下了还没兑换的。

## 四、淘宝券号的流程（一页纸）

1. 建批次：`create --name "淘宝-1000元宝-01" --kind single --count 500 --ingot 1000 --channel taobao`，记下批次 id；
2. 导出：`export --batch <id> --format txt > codes.txt`；
3. 把 `codes.txt` 整个导入淘宝的自动发货工具；
4. 买家拍下 → 自动收到券号 → 回游戏充值页的兑换码输入框输入；
5. 库存快用完时重复 1~3 建下一批；补货时用 `--unused` 重新导出；
6. 买家退款：用 `void` 作废；买家说码不对：用 `lookup` 查；月底：用 `stats --channel taobao` 对账。

## 五、常见问题

- **玩家提示“输错次数太多，请稍后再试”**：每个账号每小时最多失败 10 次（码不存在、格式不对、已被用、过期、已领过、已被领完都算失败），超过后 1 小时内所有兑换都被拒绝；成功的兑换不算失败。让玩家等一会儿再试，不要帮他“解除”，也没有解除的命令。
- **玩家提示“背包里某道具已满”**：奖励里有道具、而玩家这种道具已经到 99 张。码**没有作废**，让他先用掉一些再兑换。
- **玩家提示“已被使用”**：用 `lookup` 查这个码是不是别人兑了；一次性码只能被一个账号用一次，先到先得。
- **通用码提示“你已经兑换过了”**：这个码同一账号只能兑一次，不是故障。
- **导出的文件第一行/最后一行混进了奇怪的日志**：脚本默认已经关掉了诊断日志；如果你的环境里设了 `DIAG_LOG=1`，请去掉再导出。
- **命令报错**：脚本会打印出错原因和用法，常见的有：`未知参数 --xxx`（参数名写错）、`缺少 --xxx`（必填的没写，如 `--name`）、`--ingot 必须在 1..100000 之间`（面额超范围）、`--count 必须在 1..10000 之间`（数量超范围）、`--xxx 缺少值`（批次名带空格却没加引号）。还有一个常见原因是漏了 `--`：必须写成 `npm run redeem -- create ...`，不然参数会被 npm 吃掉。

## 六、数值与规则速查

| 项 | 值 |
|---|---|
| 码格式 | 16 位，显示成 `XXXX-XXXX-XXXX-XXXX`，字符是 0-9 和 A-Z 去掉 I、L、O、U；不区分大小写，空格和横线可带可不带 |
| 元宝奖励 | 1 到 100000 / 码 |
| 道具奖励 | 每种 1 到 99 张，道具必须在售 |
| 一次性码单批数量 | 1 到 10000 |
| 通用码人数上限 | 必填 `--max`，一个批次只有一个码 |
| 失败次数限制 | 每账号每小时 10 次，超过后拒绝 1 小时 |
| 兑换记录保留 | 兑换记录永久保留（跨赛季）；失败尝试记录只保留 7 天 |
